# SpotHop Web: audit findings and remediation report (Nov 2026)

**Project:** a social app for skate spots. The stack is React 19, Vite, MUI, TanStack Router and Query,
Jotai, Supabase (Postgres with RLS, Auth, Storage, Realtime, Edge Functions), and Vercel (a PWA). It has
about 220 source files and 140 test files. The audit covered architecture, security, performance,
bandwidth, DRY, and code smells. The live Supabase project was also checked with read-only queries and
the Supabase advisors, so these are not just code-reading findings.

## Original findings

**Critical or high (security)**
1. **RLS on `conversation_participants`:**
   - Any signed-in user could add themselves to any conversation and read its messages.
   - Any participant could edit any other participant's role and status.
2. **Storage:**
   - A catch-all policy let any signed-in user upload to any bucket, and a second one allowed public
     reads on all buckets.
   - Avatar uploads only worked because of that open policy: the code writes `<uid>.webp` but the
     policy required `<uid>`.
   - No file size or MIME limits existed on any bucket.
3. **Feed RPCs:** `get_global_feed_content` and `get_following_feed_content` were `SECURITY DEFINER` and
   trusted a client-supplied `p_user_id`. Anonymous callers could read another user's liked and followed
   state. Their `search_path` was also unpinned.
4. **Report-based auto-moderation was dead code.** `content_reports.target_type` only allows `spot`,
   `comment` and `media`, but the feed filtered on `'photo'` and `'video'`. There was also no unique
   constraint on `(user, target)`. (The first read of this was wrong: it was initially reported that one
   user could hide any content. The live check showed the rule simply never matched.)
5. **33 `SECURITY DEFINER` functions were callable by the anonymous role,** including trigger functions.
6. **Client issues:**
   - The query cache persists for 7 days and is not cleared on logout.
   - A real conditional-hooks bug in `FeedCommentDialog`.
   - A `user!` crash on refresh in the chat room.

**Bandwidth and performance**
- The feed rendered full-size photos because the RPC read a legacy thumbnail column that new uploads
  never fill.
- The chat inbox downloaded every message of every conversation (`messages (*)`), just to compute the
  last message and unread count. The chat details query also loaded the whole thread and discarded it.
- Google Maps JS (with Places) loaded on every route, and the app bar rendered "Loading..." until it
  finished.
- Spot pages called the Geocoding API on every view even though addresses are stored.
- Uploads were cached for only 1 hour despite having unique filenames.
- 26 foreign keys had no index, and `spots` had no latitude or longitude indexes (the map's viewport
  query filters on them).

**Code health and hygiene**
- 702 ESLint errors, with no lint or CI gate. 283 `src/` imports, 199 `../` imports and 33 `@/` imports,
  against a written rule to use `@/`.
- Committed debug files (a 166 KB `errors.txt` and others), a README that was the Vite template, and a
  package named `"nothing"`.
- Supabase migrations had drifted from production's recorded history in both directions. Eleven prod
  migrations were missing from the repo, about 17 repo files were never recorded, some shared version
  numbers, and one repo migration was never applied.

## Changes made (all pushed to `main`; CI green)

**Database (applied to production; SQL is in `supabase/migrations/`)**
- A security migration fixed the participant policies (creator or admin insert, self or admin update and
  delete, plus a trigger that blocks role changes). It dropped the catch-all storage policies, fixed the
  avatar policies, and added bucket limits (`spot-media`: 50 MB, webp or mp4; `avatars`: 2 MB, webp). It
  added a unique constraint on reports, revoked API access to 14 trigger functions, revoked anonymous
  access to 7 user-action RPCs, pinned `search_path`, and added 28 indexes.
- A feed RPC migration made the RPCs use `auth.uid()` (the `p_user_id` parameter is now ignored), return
  the 800px thumbnail, match the real report types with distinct-reporter counting, pin `search_path`,
  and drop a stale overload.
- A new `get_inbox_summary()` RPC (`SECURITY INVOKER`) returns the last message and unread count in one
  indexed query.
- The previously unapplied lat/lng indexes were applied, and `supabase/migrations` was synced with
  production history. The files and the recorded history now match one-to-one (36 versions).
  `supabase/README.md` documents the conventions.

**Client**
- Photos render as thumbnails in the feed. The chat inbox uses the RPC. Threads load the latest 50
  messages with a "Load earlier messages" button.
- Google Maps loads lazily via a new loader (`src/lib/googleMaps.ts`) on first search interaction, and
  the app bar no longer waits on it. The now-unused `@react-google-maps/api` dependency was removed.
- Spot addresses come from stored fields, and Google is called only when no street address exists. New
  uploads get a 1-year cache header.
- Fixed the crash on refresh in the chat room, the conditional hooks, and the dark-mode chat styling.
  The message input now keeps focus after sending.
- Map tiles work again with a CARTO API key (via an env var).
- Generated database types and typed the client (`createClient<Database>`). That surfaced 45 type
  errors, which were fixed. They revealed real bugs: a call to an RPC that doesn't exist (the unused
  module was removed), liked-photo thumbnails reading a non-existent column, and chat titles that never
  fetched `displayName`.

**Quality and process**
- ESLint went from 702 errors to 0 errors. It now allows `any` in tests, warns on it in app code (135
  warnings remain), and enforces `@/` imports.
- A codemod updated 644 imports across 274 files to `@/`.
- GitHub Actions CI (typecheck, lint with a warning cap, tests with a coverage ratchet at 58/50/53/61)
  was added. It caught a real flaw, which is that tests depended on a developer's `.env`, and that is
  fixed.
- Repo cleanup: debug files, generated files and an unused ffmpeg copy were removed, and the README,
  `.env.example`, docs, package name and `.gitignore` were fixed.
- Smaller fixes: the PWA cache rule is project-agnostic, GitHub Actions run on Node 24 versions, and the
  deprecated tsconfig `baseUrl` was removed.

**Verification:** typecheck, 0 lint errors, 549 tests, the production build, the security advisors, and
read-only impersonation queries against the new RPCs.

## Open items and limits (worth scrutinizing)
- **Not tested end to end:** it was not possible to sign in as a user during the audit. RLS and RPC
  behavior was confirmed by reading the live policies, running advisors, and impersonation queries, plus
  manual checks of chat creation, member removal and avatar upload.
- **Dashboard settings that need the project owner** (there is no tool for Auth config): Site URL and
  Redirect URLs, OTP expiry, and custom SMTP before real users arrive. Leaked-password protection needs
  the Pro plan.
- **Remaining advisor warnings are intentional:** the feed and follow RPCs stay anonymous-callable (the
  logged-out feed needs them), the `is_admin`, `is_banned` and `is_chat_participant` RLS helpers are still
  callable, and PostGIS sits in the `public` schema.
- **Known limitations:**
  - Replaying `migrations/` into an empty database is not guaranteed to work, because the earliest
    tables exist only as `remote_schema` dumps.
  - Coverage is about 59% statements against an 85% goal.
  - 135 lint warnings remain: 123 `any` and 12 `exhaustive-deps`.
  - Two typed-boundary casts (profile upserts and contest `criteria`) are deliberate and commented.

**Good areas for a second opinion:** the RLS policies in
`20261107000000_security_hardening_chat_storage_reports.sql`, the feed RPCs in
`20261107010000_feed_rpc_auth_uid_thumbnails_moderation.sql`, and whether the remaining
anonymous-callable functions are acceptable.
